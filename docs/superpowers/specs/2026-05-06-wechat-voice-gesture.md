# 微信式语音输入手势交互设计

## 概述

改造 AI 助手的语音输入交互，从简单的"按住说话"升级为微信式手势交互：按住麦克风后，手指可滑动到"取消"或"转文字"区域，松手后执行对应操作。选择"转文字"后弹出底部编辑面板，用户可编辑识别结果后发送。

## 需求

1. 按住麦克风开始录音，按钮上方浮现两个扇形手势区域
2. 手指向左上滑动到"松开取消"区域，松手后取消本次录音
3. 手指向右上滑动到"转文字"区域，松手后停止录音并打开编辑面板
4. 手指未滑动到任何区域直接松手，停止录音并直接发送识别文字
5. 编辑面板显示识别文字，用户可修改后点击发送或取消
6. 手势区域在手指滑动时实时高亮反馈

## 方案

采用**模态编辑面板方案（方案 B）**：

- 手势检测：`react-native-gesture-handler` PanGestureHandler
- 动画：`react-native-reanimated` 驱动区域高亮和面板滑入/滑出
- 编辑面板：底部滑出模态，含多行 TextInput 和操作按钮

## 依赖

```bash
cd app && pnpm add react-native-gesture-handler react-native-reanimated
```

`react-native-reanimated` 需在 `babel.config.js` 中配置 plugin。

## 状态管理

### 新增状态

```ts
type VoiceState = "idle" | "recording" | "editing";
```

- `idle`：未录音
- `recording`：正在录音，显示手势区域
- `editing`：显示编辑面板，等待用户操作

### 状态机

```
idle ──[按住]──► recording
recording ──[松手在取消区]──► idle（放弃识别结果）
recording ──[松手在转文字区]──► editing（打开面板）
recording ──[松手在无区]──► idle + 直接发送文字
editing ──[点取消]──► idle
editing ──[点发送]──► idle + 发送文字
```

## 手势区域定义

以麦克风按钮中心为原点，定义两个扇形区域：

- **取消区**：第二象限（x < 0, y < 0），角度范围约 120°~180°，距离阈值 ≥ 40dp
- **转文字区**：第一象限（x > 0, y < 0），角度范围约 0°~60°，距离阈值 ≥ 40dp

手势检测在 `onChange` 中实时计算手指相对按钮中心的极坐标（距离 + 角度），判断落入哪个区域。

## UI 交互

### 录音中界面

- 麦克风按钮上方显示两个扇形背景区域（半透明圆弧）
- 取消区显示 "松开取消" + × 图标（红色系）
- 转文字区显示 "转文字" + 键盘图标（品牌色）
- 手指移入区域时，该区域透明度增加 + 图标放大
- 音波动画继续显示（复用现有 waveRow）

### 编辑面板

- 从底部滑入，高度约 45% 屏幕
- 顶部标题栏："识别结果" + 关闭按钮
- 主体：多行 TextInput，预填充识别文字，自动聚焦，显示光标
- 底部按钮栏：「取消」（outline）| 「发送」（主色填充）
- 面板外点击或下滑可关闭（取消）

## 边界情况

### 录音时间过短（< 1s）

直接显示 Toast "说话时间太短"，不进入编辑面板。

### 无识别结果

直接显示 Toast "未能识别语音"，不进入编辑面板。

### 编辑面板中按 Home 键或切换应用

面板保持打开，文字保留。返回应用后可继续编辑。

### 同时触发 AI 回答状态

编辑面板仅在 `state === "idle"` 时可用。如果 AI 正在 streaming，麦克风按钮已变为取消按钮，无法启动录音。

## 不涉及的范围

- **语音消息发送**：当前系统不支持发送音频文件，仅支持文字
- **语音转文字引擎替换**：继续使用 `@react-native-voice/voice`
- **多语言识别优化**：保持现有的 `pickVoiceLocale()` 逻辑
